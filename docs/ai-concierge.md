# AI Concierge (Optional Narrative Layer)

Compass Concierge is grounded in a strict trust model:

- **Compass chooses recommendations deterministically**
- **AI only explains and formats the chosen itinerary**

AI does not pick places, events, deals, or restaurants.

## How it works

1. Concierge preferences are selected in `/concierge`.
2. `generateConciergeTrip(...)` builds the deterministic Compass trip.
3. Optional AI narration can be requested from `POST /api/concierge/ai`.
4. The API route sends only approved SouthernVT trip fields to the model.
5. The route calls OpenAI **Responses API** from server-only code.
6. The model returns structured copy:
   - `summary`
   - `whyThisTrip`
   - `localTips` (3 tips)

Route implementation:

- `app/api/concierge/ai/route.ts`
- Uses `client.responses.create(...)` from the official OpenAI JS SDK.

## Grounding rules

Prompt construction is centralized in:

- `lib/concierge/buildConciergeAIPrompt.ts`

Only these data types are included:

- selected place names/descriptions from existing data
- selected collection and guide names
- selected event/deal names (if present)
- user preferences

The prompt explicitly forbids invention of:

- places
- hours
- restaurants
- events
- deals

If data is missing, the narrative must say so briefly.

Compass remains the recommendation authority: AI does not select or rank destinations.

## Feature flag

- Flag key: `aiConcierge`
- Default: `false`
- When disabled, Concierge works exactly as Compass currently does.
- When enabled, the user sees the **Enhance with AI** option under Concierge results.

## Environment variable

Set on server only:

```env
OPENAI_API_KEY=
```

Do **not** expose this as `NEXT_PUBLIC_*`.

The OpenAI SDK reads this key in server runtime. The key is never sent to the browser.

## Fallback behavior

Fallback narrative is generated by:

- `lib/concierge/fallbackConciergeNarrative.ts`

Fallback is returned when:

- `aiConcierge` is disabled
- `OPENAI_API_KEY` is missing
- AI request fails
- model output is empty

Parsing behavior:

- `lib/concierge/parseConciergeAIResponse.ts` attempts JSON parsing first.
- If plain text sections are returned, it safely maps summary/why/tips.
- If parsing still fails, all model text is kept in `summary` and fallback tips are used.

This keeps Concierge reliable and avoids trust-breaking fabrication.

## Why this protects trust

Because recommendation selection stays deterministic in Compass, editorial quality and explainability remain auditable. AI is constrained to narrative polish on already-chosen SouthernVT records, preserving the platform principle:

- **Premium can be bought.**
- **Verified and trusted recommendations must be earned.**
